# Strange Showdown

아이템을 활용한 전략 플레이가 중심이 되는 3인칭 시점의 라스트맨 스탠딩 게임입니다.

서부 마을을 배경으로 최대 5명의 플레이어가 경쟁합니다. 공격 시 사거리 내의 대상이 자동으로 조준되기 때문에, 전투의 결과는 조작 숙련도가 아니라 언제 누구를 공격할지와 한정된 자원을 어디에 사용할지에 대한 판단에서 갈립니다. 피해를 받지 않고 성장할수록 자신의 목에 걸린 보상이 커지는 현상금 시스템, 스테미너와 행동 횟수를 배분해야 하는 자원 관리, 그리고 탈락한 플레이어가 유령이 되어 유령 보안관에 빙의해 생존자를 위협하는 구조를 통해 게임 전반에 걸쳐 지속적인 상호작용과 전략적 판단을 유도합니다.

승리 조건은 최후의 1인 생존과 100골드 확보 후 기차역 상호작용 두 가지로 나뉘며, 플레이어는 전투와 자원 수집 중 어떤 경로로 승리를 노릴지 선택할 수 있습니다.

클라이언트는 Unreal Engine 5로, 멀티플레이 서버는 Windows IOCP 기반의 전용 서버로 각각 직접 구현했으며, 양측이 공유하는 프로토콜과 상수는 별도의 `Common` 모듈로 분리해 관리합니다.

## 주요 기능

### 게임 시스템

- **이중 승리 조건** — 최후의 1인 생존 외에도 100골드를 확보한 뒤 기차역 오브젝트와 상호작용하여 승리할 수 있습니다. 전투 회피형 플레이와 공격적 플레이가 모두 유효한 전략이 되도록 설계되었습니다.

- **현상금 시스템** — 피해를 받지 않은 상태에서 누적 피해량과 골드 획득량이 일정 기준을 넘으면 현상금 단계가 상승합니다. 현상금 보유량만큼 자신이 받는 피해와 자신을 공격한 상대가 얻는 골드가 증가하며, 피해를 받으면 관련 수치가 모두 초기화됩니다. 현상금 게시판 UI를 통해 전체 플레이어의 현상금 보유량을 확인할 수 있습니다.

- **자동 조준 기반 공격 판정** — `USTAttackTraceComponent`가 매 프레임 시야 검사를 수행해 사거리 내의 대상을 자동으로 조준하고, 대상이 바뀔 때마다 추적 상태를 갱신합니다. 조준당한 플레이어에게는 `USTTargetIndicatorComponent`를 통해 자신을 겨누고 있는 상대의 수가 표시되어, 조준 정확도 대신 위치 선정과 공격 시점 판단이 전투의 핵심이 되도록 구성했습니다.

- **턴 기반 자원 순환** — 일정 주기의 턴 타이머마다 전체 플레이어의 총알과 스테미너가 회복되고, 무작위 맵 오브젝트가 활성화됩니다. 활성화된 구역 주변에만 아이템이 스폰되어 플레이어의 이동과 접촉을 강제합니다.

- **구역 판정 및 위험 지역** — `ASTAreaVolume`이 은행·교회·술집·기차역·제단 등 각 구역의 진입과 이탈을 감지해 HUD의 현재 지역 표기와 위험 지역 타이머를 갱신합니다. 위험 지역에 오래 머무르면 거리와 무관하게 유령 보안관의 추적 대상이 됩니다.

- **추가 미션 시스템** — 아이템을 통해 무작위 미션을 획득하고 제한 시간 내 달성 시 보상을 받습니다. 미션 데이터는 데이터 테이블로 관리되며, 시작·진행·완료 각각에 대한 델리게이트를 통해 미션 위젯에 실시간으로 반영됩니다.

### 유령 보안관 AI

- **위험 신호 UI** — 추적 대상과 보안관은 선으로 연결되고, 인내심 게이지 잔량에 따라 추적 타이머 위젯의 표시가 단계별로 변화합니다. 보안관이 화면 밖에 있을 경우 화면 외곽에 방향 지시 UI로 표시됩니다.

- **탈락자의 보안관 빙의** — 탈락한 플레이어는 유령 상태로 전환되어 지형을 통과하며 관전하고, 유령 게이지가 가득 차면 보안관에 빙의해 일정 시간 직접 조종할 수 있습니다. 탈락 이후에도 게임에 개입할 수 있는 역할을 부여해 이탈을 방지합니다.

### 아이템과 상점

- **인벤토리 및 퀵슬롯** — 데이터 에셋(`STItemDataAssetBase`) 기반으로 아이템 정보를 정의하고, 전용 드래그 앤 드롭 오퍼레이션을 통해 인벤토리와 퀵슬롯 간 아이템을 이동할 수 있습니다. 슬롯 변경은 이벤트 디스패처로 UI에 전파되며, 툴팁 위젯으로 아이템 정보를 표시합니다.

- **아이템별 효과 클래스 분리** — `USTItemUseEffect`를 기반 클래스로 두고 헬멧·고기·위스키·바퀴·무기 강화·수상한 편지 등 아이템마다 별도의 효과 클래스를 구현했습니다. 사용 가능 여부 검사(`CanUse`)와 실제 적용(`Use`)이 분리되어 있어, 새 아이템을 추가할 때 인벤토리·상점 로직을 수정하지 않아도 됩니다.

### 맵과 오브젝트

- **메시 절단** — 망치 타격 지점과 노멀 벡터를 기준으로 대상 메시를 실제로 절단하는 `ASTSliceableActor`를 두고, 이를 상속해 파괴 가능한 오브젝트를 구현했습니다. 저주받은 금덩이(`ASTMineral`)는 외곽 메시와 내부 메시를 분리해 단계별 파괴 연출을 구성하고 파괴된 양에 비례해 골드를 지급하며, 일정량 이상 파괴되거나 제한 시간이 지나면 해당 위치에 유령 보안관이 생성됩니다. 건물의 출입문 역시 동일한 구조로 파괴할 수 있어, 정문을 우회하거나 새로운 진입 경로를 여는 전술적 선택지를 제공합니다.

- **상호작용 인터페이스 기반 맵 오브젝트** — `IInteractable` 인터페이스와 `ASTMapObjectBase`를 상속받아 은행 금고, 교회 단상, 술집 테이블, 기차역 표지판, 제단 등을 각각 구현했습니다. 오브젝트마다 골드와 스테미너를 소모해 부활·현상금 초기화·탄환 장전 등 서로 다른 효과를 제공하며, 활성화될 때마다 1회씩 사용 가능합니다.

- **미니맵 및 전체 지도** — 상시 표시되는 미니맵과 단축키로 여는 전체 지도를 각각 별도 액터로 구현했습니다. `ISTMiniMapTargetInterface`를 구현한 액터는 자신의 위치와 아이콘 텍스처를 제공하기만 하면 미니맵에 자동으로 표시되어, 표시 대상을 추가할 때 미니맵 로직을 수정할 필요가 없습니다.

### 네트워크

- **Common 모듈 분리** — 패킷 구조체, 상태 열거형, 플레이어·아이템·맵 상수를 서버와 클라이언트 프로젝트 바깥의 독립 디렉터리로 분리하고, 양측 빌드 설정에서 동일한 경로를 참조하도록 구성했습니다. 직렬화 규격과 게임 상수의 불일치를 원천적으로 차단하며, 패킷은 `#pragma pack(1)`이 적용된 고정 크기 구조체로 정의됩니다.

- **IOCP 전용 서버** — Windows IOCP와 워커 스레드 풀 기반의 비동기 소켓 서버로, `AcceptEx` 기반 접속 처리와 레퍼런스 카운팅을 통한 세션 수명 관리를 구현했습니다.

- **방 단위 JobQueue** — 각 Room이 `concurrent_queue` 기반의 잡 큐를 보유하고 원자적 플래그로 단일 스레드 실행을 보장하여, 방 내부 로직에 대한 별도의 락 없이 데이터 경합을 방지합니다. Room은 대기·로비·인게임 상태를 가지며 방 생성, 입장, 준비, 게임 시작, 채팅, 아이템 사용 패킷을 직접 처리합니다.

- **오브젝트 ID 기반 스폰 관리** — 서버의 모든 네트워크 객체가 `Object` 기반 클래스를 상속해 고유 ID를 부여받고, 클라이언트의 `USTDataManager`가 ID와 실제 액터를 매핑해 스폰·디스폰·이동·상태 갱신 패킷을 처리합니다. 레벨이 전환되어도 플레이어 정보가 유지되도록 설계되어 로비와 인게임 간 전환을 지원합니다.

- **오브젝트 풀링** — 세션, 플레이어, 룸 객체를 타입 특성(`ObjectTypeTraits`) 기반의 풀에서 사전 할당해 관리하여, 접속과 해제가 반복되는 상황의 할당 비용을 줄였습니다.

- **송수신 스레드 분리** — 클라이언트는 `FRunnable` 기반의 수신 스레드와 송신 스레드를 별도로 운용하여 게임 스레드의 블로킹 없이 통신을 처리하고, 패킷 타입별 핸들러를 맵에 등록해 디스패치합니다. 레벨 로딩 중에는 패킷 처리를 일시 정지시켜 로딩 중 도착한 패킷이 유실되지 않도록 처리합니다.

- **Local / Field 캐릭터 분리** — 조작 주체인 로컬 캐릭터와 서버로부터 위치를 동기화받는 원격 캐릭터를 별도 클래스 계층으로 분리했습니다. 플레이어·유령·보안관·로비 플레이어 각각에 대해 이 구조를 적용하여, 조작 로직과 보간 로직을 독립적으로 관리하고 사망 시 플레이어에서 유령으로의 타입 전환을 서버 주도로 처리합니다.
